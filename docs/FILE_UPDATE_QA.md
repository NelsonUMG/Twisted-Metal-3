# Actualización por archivos — estado de QA

Al abrir el lobby se consulta GitHub Releases una sola vez por ejecución. Se retiró el botón de consulta manual. Una versión nueva con `TM3Online-update.json` abre una ventana de progreso que lista los archivos descargados. Cada archivo se compara por tamaño y SHA256; se descargan solamente los diferentes o ausentes, incluidos Python, DLL, EXE, configuración de distribución y licencias. No se descargan fragmentos internos de archivos.

`tools/build_installer.py --runtime runtime --stage-only` compila TM3Lobby.exe y TM3Update.exe y prepara el payload y los assets individuales en dist/update. El manifiesto referencia blobs por SHA256. GitHub aporta también el digest de los assets. La publicación necesita incluir el manifiesto y todos sus blobs; no basta subir un commit. No se generan ZIP de distribución.

El botón Reiniciar verifica el aplicador y cierra el lobby y sus procesos propios mediante el cierre existente. TM3Update.exe se ejecuta desde la caché, espera la salida del proceso padre, vuelve a verificar los archivos, guarda recuperación temporal y reemplaza archivos. VERSION se escribe al final. Al terminar abre TM3Lobby.exe. Si falla un reemplazo, restaura los archivos previos. El registro temporal permite recuperar una aplicación interrumpida al volver a ejecutar el aplicador. No se eliminan archivos obsoletos mediante este protocolo.

Se preservan archivos INI, userdata, partidas, capturas e imágenes del juego. Los archivos idénticos conservan sus bytes y fecha de modificación. El helper se copia desde la instalación si ya coincide, evitando descargarlo otra vez. La cancelación durante la descarga no cambia la instalación.

QA ejecutada en Windows: comprobación única, versiones, progreso, cancelación, fallo de red, digest corrupto, instalador alterado, interfaz de Reiniciar y error de lanzamiento; comparación de todos los tipos, archivos sin cambios, rutas inválidas, duplicados, DLL realmente bloqueada, rollback y recuperación de transacción interrumpida. El helper congelado se probó en carpeta aislada: espera de PID, reemplazo de PY/DLL/EXE/VERSION, reinicio de un EXE fixture nativo y conservación de ajustes y partidas. Evidencia local: diagnostics/update_fixture/*/result.json. Los fixtures DLL/PY son datos de prueba; no acreditan ejecutar una versión nueva completa del juego.

Pendiente: publicar una Release probada con manifiesto/archivos, descarga pública real y actualización entre dos versiones completas de TM3. La API Releases/latest devuelve HTTP404 al comprobarla. La prueba real del instalador Inno sigue pendiente y no se instaló el compilador tras el rechazo previo. No se declara QA al 100% ni publicación final. El canal de archivos ya no necesita Inno para aplicar actualizaciones; sigue siendo necesario para la instalación inicial mediante Setup.
